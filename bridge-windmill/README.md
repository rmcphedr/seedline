# Bridge enrichment flows

Bridge owns source fetching, extraction, validation, persistence, and review state. Windmill runs the stages and shows their logs. The flow definitions in `flows/` are generated from `flows/build_flows.py` and are intended to be pushed to `f/bridge/enrichment_smoke` and `f/bridge/enrich_funding_opportunity`.

## Local setup

1. Create a shared Docker network once: `docker network create bridge_windmill`.
2. Set `ADMIN_API_KEY`, `BRIDGE_WORKER_API_KEY`, `WINDMILL_WORKSPACE`, `WINDMILL_FLOW_PATH`, and `WINDMILL_API_TOKEN` in the Bridge `.env`. Use a Windmill webhook-specific token with permission to run only this flow. Set `WINDMILL_PUBLIC_URL` to the browser-accessible Windmill address, and `BRIDGE_ENRICHMENT_CONCURRENCY` to the desired batch dispatch limit (default 3, maximum 10). The API container reaches Windmill at `http://windmill_server:8000` over the shared network.
3. Start Windmill with `docker compose -f bridge-windmill/docker-compose.yml --env-file bridge-windmill/.env up -d`, then start Bridge with `docker compose up -d --build` and run `docker compose exec api alembic upgrade head`.
4. In the Windmill workspace, create `f/bridge/api_url` with value `http://api:8000` and a **secret** variable `f/bridge/worker_api_key` with the same value as Bridge's `BRIDGE_WORKER_API_KEY`. Grant the flow's execution identity access only to these variables. Keep the worker key distinct from `ADMIN_API_KEY`.
5. Configure the Windmill CLI for that workspace. Push the smoke flow with `wmill flow push bridge-windmill/flows/enrichment_smoke.flow f/bridge/enrichment_smoke`. Push the full flow with `wmill flow push bridge-windmill/flows/enrich_funding_opportunity.flow f/bridge/enrich_funding_opportunity`. The CLI expects the `.flow` directory and reads its `flow.yaml` itself. Confirm the deployed flow paths in Windmill's Details and Triggers tab.

## First live test

Set `WINDMILL_FLOW_PATH=f/bridge/enrichment_smoke` and `BRIDGE_ENABLE_ENRICHMENT_SMOKE=1` on the Bridge API, then restart the API. From the admin opportunity page, enrich one record with a URL. The smoke flow loads that opportunity through the worker-only API and marks the Bridge job `succeeded` at `smoke_complete`. Check the same job UUID in Bridge and its Windmill run ID in Windmill. This tests the network, both credentials, ID mapping, and callback. The smoke flow does not fetch content or change review state.

After that test, set `WINDMILL_FLOW_PATH=f/bridge/enrich_funding_opportunity`, remove `BRIDGE_ENABLE_ENRICHMENT_SMOKE`, and restart the API. Set `OPENROUTER_API_KEY` on the API before running the full flow. `BRIDGE_ENRICHMENT_MODEL` defaults to `google/gemini-2.5-flash-lite`; the selected model must support JSON Schema output. Each completed OpenRouter response stores token usage, including when its structured output cannot be parsed. From the admin page, enrich one opportunity, inspect the Windmill execution link and its load, fetch, extract, validate, and stage steps, then review the proposal on the opportunity detail page. Select and optionally edit fields to apply, verify the resulting pending record, and publish it separately. A rejected proposal leaves a previously verified record untouched. Once this path succeeds, use **Enrich selected** for a batch.

For early tests without a paid model, set `BRIDGE_ENRICHMENT_MODEL=nvidia/nemotron-3.5-super-vl:free` in Bridge's `.env` and restart only the API. Bridge disables reasoning for this model so its output budget is available for structured JSON. OpenRouter's free-model rate limits apply, and NVIDIA says it logs free-endpoint inputs for service improvement; use public source pages only. A completed test job reports its model and cost in the proposal's extraction details. Switch back to a paid model when you need more reliable production extraction.

## Review and security

The full flow loads the record, identifies directory landing pages, fetches public HTML or text PDFs, extracts structured fields and source excerpts, validates them, and stages a proposal. Directory landing pages stop before extraction and are flagged `discovery_required`. Bridge saves the URL, retrieval time, and SHA-256 content hash with the source document. A staged proposal is `pending_review` and does not alter an approved or published record unless `BRIDGE_AUTO_PUBLISH_ENRICHMENT=1`. With that switch on, staging accepts every proposed field that is not marked uncertain, verifies the record, and publishes it. Uncertain fields stay unchanged. Unpublish removes the record from the public explorer and keeps it verified; a later enrichment does not publish it again. An admin can still accept selected fields, edit their values, or reject a proposal when the switch is off. Acceptance uses the normal service layer, creates a version linked to the source document, resets verification and publication, and sends the record to review. Failed jobs retain an error and can be retried. The worker key cannot approve, verify, or publish.

The Bridge API is bound to loopback on the host in local Compose. Windmill reaches it through `bridge_windmill`; the web container does not join that network. Keep `/api/internal/*` off public reverse proxies in other deployments. The worker key can call only enrichment worker routes and cannot call admin publication routes. The source fetcher rejects private IP addresses, redirects, non-text responses, and responses over 1 MB; opportunity URLs linked to a registered source must remain within its allowed domains.
